📜 Smart Contract Rules (Autonomous Logic)

1
Initial State: Every new agreement is automatically initiated in Active status upon block creation.
2
State Transition: An Active agreement can transition to Completed upon fulfillment.
3
Immutability: A Completed agreement is permanently locked and cannot be edited, completed again, or cancelled.
4
Termination Rule: A Cancelled agreement is terminal and cannot be reactivated or completed.
5
Cryptographic Non-Repudiation: Every change is secured by SHA-256 hash linking to the preceding block.

💡 How This System Works

Nine key stages of decentralized blockchain agreement lifecycle
1

Genesis Block Created

The blockchain initializes with Block #0 having previousHash = "0" as the root trust anchor.

2

Parties Form Agreement

Party A and Party B agree upon terms, scope, validity timeframe, and contract amount.

3

Transaction Formed

The agreement payload is packaged into a structured immutable transaction object.

4

New Block Appended

A new block is created with an incremented index, timestamp, transaction data, and previous block's hash.

5

SHA-256 Hash Generated

Browser Web Crypto API generates a unique 64-character hexadecimal SHA-256 digital fingerprint.

6

Previous Hash Stored

Each block explicitly stores the previous block's hash, forming an unbreakable forward chain.

7

Sequential Chain Built

Block 0 (Genesis) → Block 1 → Block 2 → Block 3 creates a cryptographic ledger.

8

Audit & Verification

Any party can verify agreement validity by recomputing SHA-256 hashes across all blocks.

9

Tamper Detection

If even a single character in an agreement is altered, hash mismatch instantly exposes the tampering.

Problem Statement

Traditional paper and centralized digital agreements suffer from vulnerabilities including manual record management, unauthorized back-dated alterations, counterparty disputes, and lack of verifiable historical audit trails.

Blockchain Solution

Agreements are recorded as cryptographic blockchain transactions. Each block is permanently linked to the previous block using SHA-256 cryptographic hashes, making any unauthorized modification immediately detectable.

System Flow

Party → Agreement → Smart Contract Rules → Blockchain Transaction → Block → SHA-256 Hash → Verification
